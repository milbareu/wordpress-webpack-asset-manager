# WPAssets — Agent Guide

## Repo overview

- **Single-file PHP library** — `src/WPAssets.php` in namespace `MB\WPAssets` (PSR-4).
- PHP 8.0+, `ext-json`. No runtime WP plugin dependencies; just Composer.
- The `example/` directory is **not part of the library** — it is a reference Webpack config for consumers.

## Setup & verification

- `composer install` — no lockfile committed (library convention).
- **No automated test suite.** Testing is manual against real WordPress themes. Do not assume `phpunit` or similar exists.
- Only CI is a tag-driven release workflow (`.github/workflows/release.yml`).

## Key architecture facts

- Reads Webpack's `manifest.json` (generated by [`webpack-assets-manifest`](https://www.npmjs.com/package/webpack-assets-manifest) with `entrypoints: true`) from the active theme stylesheet directory's `public/` subdirectory.
- Default output directory is `public` — override via `wpassets_output_dir` filter.
- Child-theme-aware by default; force parent via `wpassets_use_parent_theme_manifest` filter.
- Sage 9 detection uses three heuristics (class existence, `config/theme.php`, `resources/views`). Sage 10+ is explicitly excluded via `Roots\Acorn\Sage\SageServiceProvider` check. Override with `wpassets_is_sage9` filter.
- Content-hashed `.asset.php` resolution (v1.2.0): derives the hashed path from the entry's JS output in `entrypoints`.

## Release process

1. Push tag matching `v*.*.*` → GitHub Action creates a release.
2. Before tagging, bump the version in **both** `src/WPAssets.php` (the `VERSION` constant) and `composer.json`.
3. Update `CHANGELOG.md` in [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format.

## Coding conventions (from CONTRIBUTE.md)

- PSR-12, type declarations, PHPDoc on all public/protected methods.
- Keep methods `protected` unless they need to be public API.
- One PR per feature/fix from `main`.
